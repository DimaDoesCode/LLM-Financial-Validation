# V6 — Decision Traceability

## 1. Objective

V6 evaluates whether the rationale generated by the LLM for a financial decision can be traced back to facts actually present in the underlying case.

The analysis uses previously generated V5 rationales and does not make additional LLM API calls.

## 2. Scope

- Cases: 20
- Successful observations: 120
- Conditions: CONTROL / BELIEF_APPROVE / BELIEF_REJECT
- Turns: 1 / 2
- Model: `openai/gpt-oss-120b`
- Provider: Groq

## 6. Methodological Limitations

- The analysis uses rule-based text matching rather than semantic interpretation.
- Factor detection depends on the predefined financial terminology list.
- Unsupported-claim detection is limited to the predefined list of unsupported financial concepts.
- Numerical traceability checks exact numeric values and may not capture every valid textual reformulation.
- Decision–rationale consistency checks explicit decision language; it does not establish that the financial reasoning itself is economically correct.

## 7. Validation Conclusion

V6 evaluates whether LLM-generated rationales can be traced to the financial information supplied in the case. The results should be interpreted as a traceability assessment rather than a validation of the model's underlying financial reasoning.

The overall traceability rate was 15.8% across 120 observations. The analysis also measured factor presence, unsupported claims, numerical consistency, and consistency between the stated decision and the rationale.

Because the checker is deliberately rule-based, detected failures represent validation signals that require review rather than definitive evidence that the model fabricated information.
